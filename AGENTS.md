## What this repo is

Facundo's job-search repo: CV sources (Typst), cover letters, the daily job
digest, and the tracking of applications. The CV is for **first formal IT
job** roles (trainee / junior / internship in development, IT support, QA,
functional analysis, automation) — not senior positions.

## THE RULE: one interface, forever

There is **exactly one** CV design: `diseno.typ`. Treat it as a design system.

- `diseno.typ` is the only file allowed to declare `set page`, `set text`,
  `set par`, `set list`, colors, font sizes, and the macros `section`,
  `entry`, `row`, `header`, `footer`, `cv`.
- A new CV is **data + a 10-line file**. It must never restyle anything.
- If something does not fit on one page or looks wrong, fix it **once** in
  `diseno.typ` and recompile every variant. Never patch the look inside a
  variant.
- Never introduce a second font family, a second palette, a photo, columns,
  icons, or a sidebar. The current shape is deliberate: one column, A4, Lato,
  petrol `#17324D`, blue `#2563EB`, gray `#374151`, no photo — ATS-safe.

## Files

| File | Role |
| --- | --- |
| `diseno.typ` | **The design.** Tokens + macros. Nobody duplicates it. |
| `contenido.typ` | **The content.** Contact data, profile, skills, experience, projects, education, as data. Single source of truth. |

## Creating a tailored CV (the only sanctioned way)

```typst
// variantes/qa-soporte.typ
#import "../diseno.typ": *
#import "../contenido.typ": *

// 1) headline: ONE target, not four.
#show: cv.with(
  headline: "QA / Soporte IT · Estudiante de Desarrollo de Software",
  contact: contacto,
  links: links,
)

// 2) profile: rewrite 2-3 lines against the posting's wording.
#section("Perfil")[#perfil]

#section("Competencias")[
  #for (i, (label, items)) in competencias.enumerate() {
    if i > 0 { linebreak() }
    [ #text(weight: "bold", fill: petrol)[#label:] #items ]
  }
]

// 3) projects: pick and order. Two is the sweet spot.
#section("Proyectos")[
  #for key in ("fleetops", "av") { entry(..proyectos.at(key)) }
]

#footer(disponibilidad)
```

Vary only: `headline`, the profile paragraph, which `proyectos` keys appear
and in what order, and — when the posting demands it — the order of the
`competencias` rows. Everything else is fixed.

## Build and verify

```bash
typst compile cv.typ                                   # → cv.pdf
pdfinfo cv.pdf | grep Pages                            # MUST print "Pages: 1"
typst compile --format png --ppi 140 cv.typ /tmp/cv.png  # visual check
```

Verification before delivering any CV: **exactly 1 page**, **85-92 % of the
page filled** (measure the PNG: content must not end above 80 % or below 95 %),
no bullet ending in a disclaimer, no duplicated fact across sections, no
visible `\@` or escaped characters in the text layer (`pdftotext -layout
cv.pdf -` shows what ATS parsers read).

Page fill is regulated in `diseno.typ` by `par-leading`, `par-spacing`,
`list-spacing`, `section-gap` and `entry-gap` — **not** by adding filler
bullets.

## Content rules

- **One bullet = one line.** If a bullet needs a second line, cut words, not
  the fact. A recruiter skims: density is the enemy.
- The main experience goes first with **two** bullets; everything older gets
  **one** bullet. Academic projects get **one** bullet; deployed projects get
  two.
- Short, verb-first phrases. No "con el objetivo de", no adverbs, no filler.
- Honest and specific. Never invent tools, metrics, or responsibilities Facundo
  has not confirmed.
- Never close a project bullet with what is missing ("testing pending",
  "not deployed"). State what was built; if it is a design-only academic
  project, say "alcance académico: diseño, sin implementación".
- No fact repeated twice (grade, English level, "resolución de incidencias").
- English level: "inglés técnico: lectura de documentación" — **no dates, no
  "en curso"** until the classes actually start.
- Dates: always `Mon YYYY – presente` or a plain year. Never leave a project
  without a date.
- A deployed project always links its public demo (`link-url`).
- Do not list a project before it is finished.

  the original serif template (typst-cv). Still compiled and published to

  them, but do not use this look for new CVs.

  re-running that script overwrites the file. Historical record only.
